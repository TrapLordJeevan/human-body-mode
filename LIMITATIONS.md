# Limitations and unverified claims

## Optional human-behaviour profile (0.1.2)

- This is a seeded heuristic, not a model fitted to measured human typing. Typo neighbours use a simplified QWERTY row ordering and false starts are three-letter synthetic prefixes, not realistic semantic revisions. Mistakes apply only to eligible ASCII editor letters (not the first chunk replacing a selection); they do not affect terminal commands or non-ASCII text. Defaults are off.
- Normal interruption cleanup removes transient wrong text only while it still matches the recorded prefix. External user edits are preserved. A hard crash or edit failure during a correction can leave transient wrong characters in an unsaved/autosaved file; there is no transactional rollback. Use disposable copies, and leave mistakes off for a correctness-only baseline. Live crash/restart during a typo has not been verified.
- Automatic-break budgets and absolute deadlines are checkpointed once per second; pending unexpired deadlines are honoured on subsequent typing. A hard crash can lose the latest checkpoint interval. Manual Resume or clock Reset intentionally skips/clears pending automatic breaks. Automatic-break wall time runs even while physical input is manually paused; it excludes offline downtime from the completed break-duration counter. Physical-action and automatic-break time are separate, not additive to queue wait.
- Workspace profiles persist in VS Code workspace state. The PRNG sequence restarts on editor reload; full bit-exact crash continuation is not implemented. Exports capture the current profile, not every historical setting change: pin parameters for a trial or export before changing them. As before, same-user/operator tampering is outside proven enforcement.

- One small real Haiku turn successfully used Read and replied verified. Full model-driven physical editing, subagent behaviour, and the complete live competition flow remain unverified until `scripts/real-claude-e2e.sh` is run.
- The VSIX was installed into an isolated code-server 4.109.5 profile. Real MCP/editor typing, saving, pause/resume, terminal Mod rendering, WPM controls and timed-break controls passed live smoke checks. This does not verify desktop VS Code Remote–SSH, editor undo/redo, multicursor or crash UI. See `docs/UI-VERIFICATION.md` for the exact boundary.
- The Mod API is experimental/version-sensitive. The implementation was validated against Claude Code 2.1.294. Starting with `--safe-mode`, `--bare`, or disabled hooks removes the Mod; the supervisor must reject that launch.
- A host user can disable the Mod/extension, alter clocks, or edit files directly. This is a supervised benchmark control, not a hostile multi-tenant security boundary.
- Mod denial is backed by process/filesystem isolation only in the supplied real-Claude launcher. Running plain `claude --plugin-dir plugin` relies on Mod interception and must not be called fully enforced.
- The terminal allowlist supports common Java/npm build and read-only Git commands. A competition project needing another executable must add and adversarially test it before the run.
- Build tools can write inside `target`, `build`, `.gradle`, and experiment logs. A malicious compiler plugin could abuse those areas, but cannot change source under the supplied bubblewrap boundary.
- Generated output is not a separate trusted clipboard principal: authored text generated into writable build/log files could subsequently be opened and copied as existing content. Preventing that laundering requires stronger output provenance or a pre-audited command/build pipeline. The current clipboard tests only establish that direct internal-text paste is unavailable; this remaining pathway means the benchmark is not fully enforced.
- The clipboard currently covers selected editor/file content. Terminal-output copy, system clipboard mirroring, duplicate-line, refactoring shortcuts, undo/redo automation, and multicursor automation are not yet broker actions. Manual human IDE shortcuts still work. Add these before a competition whose task materially depends on them.
- Metrics persist once per second; a hard crash can lose at most the last interval. An unfinished action is not yet journalled as an explicit aborted record. JSON/CSV are summaries, not a cryptographically tamper-evident log.
- One VS Code window has one controller. Separate VS Code windows create separate queues, so the supervisor must allow exactly one extension host/window for the target repository.

Result: ready for a supervised dry run; not yet ready to claim a fully enforced real-Claude benchmark.

## Codex adapter

- Verified against installed Codex CLI 0.162.1: real-model Two Fer completion through actual VS Code typing and sandboxed terminal tests, native writer-probe denial, 3/3 tests passed, tests unchanged, and normal session end. Offline checks verify configured servers disabled and supervisor control excluded. Live subagent inheritance, full native process isolation and Claude model-driven completion remain unverified. See docs/CODEX-BENCHMARK.md; the passing integration smoke is not a productivity benchmark.
- Codex command hooks can fail open on runtime errors, timeouts or malformed output. Our script emits denial for validation/audit failures, but a missing executable or killed hook is outside that script's control. The launcher therefore also forces the native read-only shell sandbox. This is not a verified process-wide filesystem isolation boundary: specialized/hosted tool paths, trusted plugins and independently running services remain potential bypasses. Never describe this adapter as fully enforced.
- Codex `write_stdin` does not get another PreToolUse check. We allow only short read-only native shell inspections, deny shell startup/testing/writing, and rely on the read-only shell sandbox for interactive-input edge cases. Tests/builds go through the broker's existing bubblewrap terminal. Native shell parsing is deliberately narrow; unusual inspection can use pair read.
- MCP config merges with existing servers; the launcher inventories them and disables each for the session. Unexpected server names fail the launch. Plugin-injected servers/tools and other hooks are not a fully isolated environment; supervise installation/configuration. Resumed sessions and conflicting flags are rejected.
- An editor bridge permits only one owning agent connection; separately connected subagents must submit intended edits through that owner. They cannot gain extra throughput, but independently submitting edits may fail rather than transparently queue. Real Codex subagent transport is untested.
- The companion `human-body watch` is plain terminal output, not a Codex Mod pane. Persistent blocked counts include earlier runs and do not reset with the clock. Same-user processes can access the authenticated supervisor bridge, as with Claude.
- The tested workspace explicitly uses Bash shell integration and confirmCommands=false. The previous default shell ran commands without captured output. No-shell-integration fallback still reports unknown exit/output and must not be treated as successful testing. The first full task needed operator clarification and timed out; only the separately recorded clean run is a passing timed result. Signal forwarding is regression-tested with fake CLI children, not a real-model crash/restart exercise.

## Terminal controls and launcher

The native Mod terminal controls are covered by Claude's offline test engine and a real interactive session with the live MCP backend. The control MCP endpoint is authenticated by the editor relay token, but is not a separate security principal: other same-user processes with the discovery token can operate it. Model tool calls to controls are denied; calls originating from this Mod are allowed using engine-owned `next.origin`. Trusted installed Mods and hooks can interfere with enforcement. The short launcher opts in to the plugin but does not sandbox the Claude process. `--dangerously-skip-permissions` is not an enforcement mechanism. The pane's blocked-attempt counter resets on Mod reload; the persistent audit file and VS Code status remain available.
